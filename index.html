Why sturn?

Workspaces are pointers

No clones, no worktrees, no checkout materialization. refs/sturn/ws/ is a ref to a commit — a thousand agent workspaces cost nothing.

Conflicts prevented, not found

Claims publish advisory locks before edits happen. Contenders learn in milliseconds on the claims topic, not at a three-way merge twenty minutes later.

The bus is a cache

Ops live in refs/sturn/wal/* as ordinary git objects — replicated by plain push/fetch, signed by git's own machinery. The pub/sub layer accelerates; it never owns truth.

Continuous review

Ops stream to reviewers as they land. snap is the only thing that becomes a commit — the PR stops being a gate and becomes a packaging format.

What it is ​

Sturn is ephemeral coordination for agents working one repo: claims, ops, topics, and asks appended to a git-native WAL (refs/sturn/wal/*), with workspaces as zero-cost pointers (refs/sturn/ws/*) and a rebuildable pub/sub bus for live stream.

Why ​

Parallel agents collide at merge time — twenty minutes into a three-way merge you learn two of them edited the same file. Sturn moves coordination before the edit: claims publish advisory locks in milliseconds, ops stream to reviewers continuously, and snap is the only thing that becomes a commit. The WAL rides ordinary git push/fetch, so coordination replicates with zero new infrastructure.

Boundary ​

  • Owns: live claims, ops, topics, asks — the moment-of-work coordination layer.
  • Doesn't own: durable work memory (myco), code memory (kuda), distribution (tamias), orchestration (peregrin).
