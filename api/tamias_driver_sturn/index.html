tamias-driver-sturn — the pavo view driver for a repo’s sturn coordination state.

Verbs (the tamias driver contract):

  • manifest — print the DriverManifest JSON (discovery probe; never touches repo state).

  • capabilities — {"capabilities": ["pavo"], "verbs": […]}.

  • ops — the engine ops manifest: every sturn CLI verb as a cli.<verb> wire query, derived from the engine’s own clap tree ([sturn::command]).

  • run <argv> — engine passthrough: tamias-driver-sturn run claims ≡ sturn claims. Also the child side of cli.* wire queries (ops::run_verb re-execs this same verb so engine output never touches the serve stream).

  • serve — ndjson JSON-RPC on stdio: {"op":"manifest"}, {"op":"views"}, {"op":"view","view":…,"params":{…}}, {"op":"query","query":…,"params":{…}} → {"ok":true,"result":…} / {"ok":false,"error":…}. query:"ops" answers the ops manifest; query:"cli.<verb>" runs the engine op.

  • cli <sturn argv> — the tamias bins[] shim verb (T-012): tamias bin exec runs tamias-driver-sturn cli --dir <pkg> --name sturn <argv> for a declared shim: cli bin; the two driver flags are stripped and the rest goes to sturn::run_from with inherited stdio — full engine parity (--repo/--config globals before the verb, --help, stdin-bound verbs, the unbounded daemon/sub/bridge/ mount surfaces).

Optional surface: feature mcp embeds pavo-driver-kit’s surface layer — mcp serves the ops as MCP tools on stdio, equivalent to the standalone tamias-driver-mcp surface driver, minus the PATH/discovery hop.

Which repo: each view/query resolves its own target — params.dir/params.root/params.repo → $STURN_REPO → sturn.toml’s repo.dir (same config search as the sturn CLI) → cwd. See data.rs for the exact order. Engine ops are the exception by design: cli.<verb> re-execs run in the request’s repo and lets sturn::dispatch own the outcome — writes keep the engine’s own semantics (WAL append, actor from config/$STURN_ACTOR, claim fencing). manifest/views are repo-free so pavo can enumerate drivers anywhere.

The view side is read-only: it folds refs/sturn/wal/* exactly like sturn claims/sturn log do — the WAL is the state, the tree is a projection, and views only ever read.
