Expand description

Everything tamias install <ref> WOULD do — the dry-run report behind install --plan (proposal P-005 §D.2). Produced by plan_install; nothing is dispatched to a driver and nothing is committed to the store (the content-addressed fetch-cache entry is inert without a store commit, so fetching is honest).

Fields§

§reference: String

The ref verbatim.

§manifest: PlanManifest

The fetched payload’s manifest identity.

§cache_hit: bool

Whether the payload resolved from the fetch cache.

§payload_digest: String

dir_digest of the RAW fetched payload — the digest trust and signature were assessed against. When Self::has_includes is set a real install digests the COMPOSED tree instead, so this is the honest raw-payload approximation.

§has_includes: bool

include: is non-empty — composition applies on a real install (see Self::payload_digest).

§includes: Vec<PlannedInclude>

include: entries classified without recursing installs.

§template_extends: Vec<PlannedInclude>

template.extends: parents classified the same way (store name → stored payload; ref → a real install would recursively install the parent, then materialize it at .scarab-parent/ for one parent or .scarab-parents/<i>/ for several). Empty = the manifest declares no parents. A malformed extends lands in Self::problems.

§bundled_drivers: Vec<String>

Driver files the payload ships under drivers/ (portable files plus bin/<triple>/ payloads, reported as bin/<triple>/<name>).

§consent_required: bool

Bundled drivers exist and no consent was given — a real install would refuse. Consent comes from tamias_driver::drivers_allowed (--allow-drivers / TAMIAS_ALLOW_DRIVERS=1) OR a recorded per-package consent matching this payload’s digest (the consent module — P-005 §D.3). NOTE: for include: packages the recorded digest is the COMPOSED tree’s, which a plan can’t compute — the raw-payload check may over-report consent_required there.

§driver: Option<PathBuf>

The driver a real install would dispatch to for the manifest’s kind (files when undeclared) — tamias-driver-<kind> on PATH or <tamias-home>/drivers/. None = nothing found: fine for files (built in), a problem otherwise. NOTE: resolution may run capabilities probes on discovered drivers — trusted local binaries, 10s timeout — acceptable for a plan.

§bins: Vec<String>

Declared bins[] command names (tamias bin deploy would materialize them on a real install).

§provider_services: Vec<PlannedService>

provider.services — what tamias deploy would later create. Clearly NOT part of install.

§trust: String

The trust tier the provenance earns (official/signed/ pinned/unpinned/bad, or unknown when assessment itself failed — see problems).

§signer: Option<String>

The verified signing principal, when one checked out.

§signature_status: Option<String>

The signature check’s spelling (verified/bad/unchecked) when the source carried a signature; None = unsigned (or the check itself failed — see problems).

§problems: Vec<String>

Would-be failures the real install would hit: the signature gate (enforce_signature), a missing driver for a non-files kind, refused bundled-driver consent, unresolvable include: entries. A plan SURFACES these rather than hard-failing.
