sealed: packs — age-encrypted payloads tamias carries opaquely (tamias ADR-0004 / org P-027).

A sealed pack’s payload is ciphertext only: the engine, store, cache, registry, TUI, and logs treat every payload file as an opaque blob — digest, verify, and sign work unchanged because they already operate on bytes. Tamias has no decrypt path; opening is cuora’s job, in the consumer’s context, via the content-type driver.

Layout (payload-relative):

sealed/
  recipients            # age public keys, one per line (public by design)
  registry-token.age    # age ciphertext of the secret bytes
tamias.yaml             # manifest; `sealed:` maps logical → file

This module owns the manifest-side Sealed block, its semantic checks, and check_ciphertext_only — the publish/install gate that refuses a sealed pack carrying stray plaintext.

Constants§

AGE_FORMAT
The only sealing format v1 understands — age file encryption (X25519 recipients + ChaCha20-Poly1305 STREAM), header line age-encryption.org/v1.
AGE_MAGIC
age file magic — every age-encrypted file opens with this header line. The publish/install ciphertext gate keys on it.

Functions§

check_ciphertext_only
The publish/install gate for sealed packs (ADR-0004 §2): every payload file — except the manifest spellings and the declared sealed.recipients target (a public-key list, plaintext by design) — must end in .age and carry the age magic. Declared sealed.files paths must exist. No warn-mode: a sealed pack with stray plaintext is a bug, not a preference.
has_age_magic
True when the file at path carries the age magic header.
is_age_ciphertext
True when bytes opens with the age file magic — the ciphertext marker the sealed-pack gate validates against.
