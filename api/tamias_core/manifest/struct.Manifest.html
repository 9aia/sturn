Expand description

The package manifest.

Fields§

§name: String

Bare package name — charset [A-Za-z0-9][A-Za-z0-9._-]*.

§scope: Option<String>

Optional namespace (@scope/name).

§version: Option<String>

Author-declared version (semver-ish label).

§description: Option<String>

Free-text description.

§keywords: Vec<String>

Discovery keywords — tamias search matches name + keywords + description. Each entry is charset/length-checked (is_valid_keyword).

§homepage: Option<String>

Project homepage URL — display metadata, free text.

§repository: Option<String>

Source repository URL — display metadata, free text.

§license: Option<String>

License — SPDX id or free text.

§authors: Vec<String>

Author display names (free text, one line each).

§kind: Option<String>

Content type (peregrin-bundle, myco-config, …).

§include: Vec<String>

Base packages to compose under this payload — installed store names or installable source refs. Local wins; earlier includes win over later ones.

Applied on install (tamias-install resolves each entry — store name → that entry’s payload dir, ref → a recursive install — then crate::overlay::overlays bases under the local payload; the store record’s digest covers the composed tree and the manifest rides along unchanged for provenance) and flattened at publish/pack time (tamias-publish, read-only — --keep-includes ships the raw payload instead).

§deps: Vec<String>

Direct dependencies — refs this project wants installed. Recorded by tamias add (and the TUI deps form) into the project manifest; tamias.lock pins each resolved record. tamias sync (CLI/serve/TUI) reconciles this set against the store + lock — install-if-missing-or-drifted, never removes.

§provider: Option<Provider>

provider: — the declarative runtime spec a deploy driver materializes (service units, ingress/forge hooks, health probe). Absent = a plain package with nothing to deploy.

§bins: Vec<BinDecl>

bins: — executable surfaces the package declares (P-023). tamias bin deploy materializes them into the bin dir; tamias install deploys them by default. Pure data — tamias never learns a product’s CLI shape.

§sealed: Option<Sealed>

sealed: — the pack is ciphertext-only (tamias ADR-0004 / org P-027): every payload file is age-encrypted and tamias carries it opaquely — digest, verify, and sign work on bytes unchanged; there is no decrypt path in the engine. Orthogonal to type: (type: secrets is a cuora-driver convention, not a requirement). Sealed packs reject include:/bins:/provider: — composition, bin deploys, and service specs over ciphertext are meaningless; deps: stays allowed.
