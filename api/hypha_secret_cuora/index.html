Cuora impl of hypha_secret::Secrets — the org’s shared secrets-broker adapter (ex-peregrin-secret-cuora, bupha-secret-cuora; mimus-cuora keeps its own dialect).

Each secret NAME resolves to a fixed cuora ref under the consumer’s scope: CuoraSecrets::new("bupha") maps GITHUB_TOKEN → cuora://bupha/GITHUB_TOKEN. Values are fetched through cuora so audit events, guardrails, and vault policy apply exactly as for every other consumer; the host never stores a value itself.

Two transports, selected per store via CuoraTransport:

  • cli (default) — shell cuora get/put per call. Secret resolution happens a handful of times per run/verb, so a per-call process is cheap and needs no shared mutable state.
  • serve — a persistent cuora serve child speaking the ndjson JSON-RPC wire (cuora-serve/1) on stdio — see serve/CuoraServe. Spawned lazily on first use, reused for the client’s lifetime, respawned on death. This is the transport cuora serve exists for (orchestrator embedding).

A missing cuora binary, a denied op, or an absent ref all answer None — “not here” — so the caller’s chain falls through to the legacy stores (OS keyring, env file) exactly like a keyring miss on a headless box, on either transport.

§Env-var convention

The shared crate never reads the environment itself — consumers pass their knob names to CuoraSecrets::from_env / CuoraTransport::from_env. The convention is <PRODUCT>_CUORA_BIN for the binary override (tests stub it) and <PRODUCT>_CUORA_TRANSPORT for cli/serve — e.g. PEREGRIN_CUORA_BIN + PEREGRIN_CUORA_TRANSPORT. CUORA_* and --config/--env resolution stay cuora’s own — children inherit the environment, so CUORA_ENV picks the vault env with no consumer-side plumbing (the serve child resolves env at spawn; per-request env overrides are not used).

§Process-wide default

Worth sharing under the serve transport: CuoraSecrets is cheap to construct but the serve child’s whole point is persistence — a fresh store per lookup would spawn and reap cuora serve on every secret read, worse than the CLI. Consumers that want a shared default keep their own OnceLock (the scope/env names are theirs); under cli sharing is a no-op behaviorally.

Secrets over cuora — CLI or cuora serve transport per CuoraTransport. Generic over the ref scope (the cuora://<scope>/… namespace) and the audit actor (defaults to the scope — every org consumer’s actor name equals its scope).

Persistent cuora serve client. Spawn is lazy — construction is free; the child appears on the first request. Cloning shares the child via Arc at the crate::CuoraSecrets layer; CuoraServe itself is not Clone.
