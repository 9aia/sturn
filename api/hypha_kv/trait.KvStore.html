Expand description

The key/value store port — synchronous like the file-backed reference impl (a mutex + atomic rewrite per mutation); callers on async runtimes treat it like any other quick critical section.

Addressing is {ns}/{key}: ns and key are separate segments — neither may contain / (the HTTP route shape enforces this; the port itself doesn’t police it). ns names a namespace ("config", "project", …); undeclared namespaces behave as Visibility::Public until KvStore::declare says otherwise.

Required Methods§

Source

fn get(&self, ns: &str, key: &str) -> Option<Value>

The value at {ns}/{key}, or None when absent — including for internal namespaces (visibility is a wire concern, not a store one).

Source

fn set(&self, ns: &str, key: &str, value: Value)

Upsert {ns}/{key} → value, creating the namespace as public when undeclared. Flushes to durable storage.

Source

fn delete(&self, ns: &str, key: &str) -> bool

Remove {ns}/{key}; true when a value was actually removed.

Source

fn list(&self, ns: &str) -> BTreeMap<String, Value>

Every entry of ns (empty map when the namespace doesn’t exist), keyed by key.

Source

fn namespaces(&self) -> Vec<NamespaceInfo>

Every namespace the store knows — declared or holding entries — with its visibility.

Source

fn visibility(&self, ns: &str) -> Visibility

The namespace’s visibility (Public when undeclared).

Source

fn declare(&self, ns: &str, visibility: Visibility)

Declare (or re-declare) a namespace’s visibility. Declaring an internal namespace with no entries still registers it, so a later set can’t silently publish it as public.

Source

fn import( &self, ns: &str, entries: BTreeMap<String, Value>, visibility: Visibility, )

Bulk-import entries into ns under visibility — the migration half (meta.json projects/config sections → KV). Existing keys are overwritten; other keys in the namespace survive.
