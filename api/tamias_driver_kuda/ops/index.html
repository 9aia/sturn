Module ops 

Source
Expand description

Engine ops — cli.<verb> wire queries dispatch into the kuda engine lib through this binary’s own run verb: each call re-execs tamias-driver-kuda run <argv> with cwd set to the request’s repo, so kuda::dispatch writes to the child’s captured stdout and never touches the serve loop’s ndjson stream (the engine’s emit() exits on broken pipe — one more reason ops stay out of the serve process).

ops answers the ops manifest as JSON — derived from the engine’s own clap tree ([kuda::command]), so a verb can’t exist on the CLI and be missing here: declared args become typed params (arg/opt/flag), doc strings ride along unchanged. The CLI’s globals (--config, --workspace) ride the manifest’s globals list once, not per-op.

watch/mcp/acp can never be request/response ops — they never return, so they ride surfaces instead and reach users through the bins[] shim passthrough (cli <argv> → kuda::run_from with inherited stdio) or the feature-gated mcp surface — tamias-driver-kuda cli watch ≡ kuda watch. Hidden plumbing (gen-cli-docs) stays reachable through run passthrough only.

mutates is honest: init scaffolds kuda.toml + .kuda/, sync rewrites cards + the sqlite index; status/map/ card/find/dependents/refs/doctor only read. Streaming flags would join SKIP_PARAMS — none exist among bounded verbs today (watch --poll-refs rides the surface).

Constants§

READ_ONLY 🔒
Read-only verbs — everything else (init, sync) writes kuda.toml/.kuda/ cards + the sqlite index. Mutators belong behind a deliberate trigger, not ambient view polling.
SKIP_PARAMS 🔒
Params excluded from ops — flags that turn a bounded verb into a stream, or params that must never ride argv. None today.
SURFACES 🔒
Unbounded surfaces — verbs that never return (watch’s debounced loop, mcp/acp stdio servers). They can never be request/response ops; they need inherited stdio.

Functions§

argv 🔒
cli.<verb> params → kuda argv (no argv[0] — run prepends it). Globals go first (clap accepts them either side of the verb), then the verb’s named flags, then its positionals in schema order.
kind 🔒
A clap arg → the manifest’s typed param kind — arg = positional, opt = --name <v>, flag = --name — the contract pavo-driver-kit’s surface layer renders args from.
manifest
The ops query/ops argv verb payload — self-describing so hosts and agents discover the engine surface without argv help. Globals (--config, --workspace) are accepted by every op — listed once on the manifest; the child gets them as argv flags.
op_cmd 🔒
op_of
Is query an engine op (cli.<verb>)? Returns the verb name.
param_json 🔒
push_param 🔒
Emit --<long> <v> / --<long> for one arg when params carries it — looked up by wire name (long flag), field id, and kebab-case id, so callers may spell params either way. Flags read truthiness; opts/args take every value.
run_op
Run one engine op against root: re-exec run in a child whose cwd is the request’s repo, and hand back {op, argv, code, stdout, stderr} as the query payload. ok:false is reserved for unknown ops and spawn failures — a nonzero code is the engine’s own exit status (e.g. find miss), honest data. The child’s stdin is null; the repo comes from root (driver-resolved) — unbounded/host-interactive verbs (watch/mcp/acp) are surfaces, never ops, precisely because they need inherited stdio.
scalar 🔒
A wire scalar → its argv token (numbers/bools stringify).
skipped 🔒
Args that can’t ride the wire: streaming flags (above) and clap’s own help/version actions. Globals are handled separately — listed once on the manifest, prepended in argv, never per-op (callers filter is_global_set() themselves).
values 🔒
All values of a param — arrays flatten, scalars wrap.
verbs 🔒
(name, clap spec) for every leaf verb. Hidden plumbing and clap’s help are skipped — they stay reachable through run passthrough.
