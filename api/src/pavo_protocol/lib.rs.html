3//! pavo-protocol — the canonical wire contract for the pavo viz host.
4//!
5//! Pure serde types, no I/O. Three contracts, all versioned
6//! (`protocol/v1/` JSON Schemas mirror these types):
7//!
8//! - **Driver manifest** ([`manifest::DriverManifest`]) — what a
9//!   `tamias-driver-<type>` executable answers to `manifest`: name,
10//!   surfaces it contributes to, and the views it can render.
11//! - **ViewNode IR** ([`view_node::ViewNode`]) — the declarative UI
12//!   tree a driver emits; renderers (CLI/TUI/web) interpret it.
13//! - **Wire ops** ([`wire::Request`] / [`wire::Response`]) — the
14//!   ndjson JSON-RPC convention every sibling `serve` speaks:
15//!   requests are `{"op":"…", …}`, responses are
16//!   `{"ok":true,"result":…}` or `{"ok":false,"error":"…"}`.
17//!
18//! Interaction actions ([`action`]) cut across all three: an
19//! [`Action`] is declared on the manifest, a view node, or a tree
20//! item and dispatched through the `invoke` wire op, answering an
21//! [`wire::ActionResult`]; [`manifest::MenuEntry`] entries feed the
22//! host command palette.
23//!
24//! Versioning policy: **additive-only within v1** — new optional
25//! fields, new enum variants, and new ops may appear; existing
26//! fields and variant spellings never change meaning.
