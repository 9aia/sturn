Expand description

The myco.toml-shaped config value the config loader (myco_ops::config) produces. Fields grow per phase; unknown keys are rejected so a typo fails loud instead of silently doing nothing.

Fields§

§project_dir: Option<String>

Path to the project worktree, relative to the repo root.

§default_view: Option<String>

The named view bare myco view resolves when no name is given — a repo pins its landing view, a machine ~/myco.toml pins a global one (scalar: repo layer wins).

§views: BTreeMap<String, ViewSpec>

Named declarative views — merged across config layers (P-006): repo myco.toml presets are shared, user-config presets personal; the user layer wins a name collision.

§verbs: BTreeMap<String, ConfigVerb>

Config-declared verbs (P-007) — merged like views, but the repo layer wins collisions (repo verbs are shared surface, personal verbs don’t override them). Builtins win over both at resolution.

§kinds: Vec<KindSpec>

[[kinds]] — user item kinds layered over the prelude (P-008). A prelude name shadows that spec (prefix stays locked); new names extend the table. Merged like verbs: the repo layer wins a name collision — a repo’s kind vocabulary is shared surface.

§sync: Option<SyncConfig>

[sync] — ledger-branch sync policy. None = defaults. Repo layer wins the table like the scalars.

§index: Option<IndexConfig>

[index] — org-index designation (ledger = "org"|"none"). The index universe reads the repo-layer myco.toml directly, so a user-layer table can’t leak a global designation into every repo.

§cycles: Vec<CycleConfig>

[[cycles]] — named iteration windows (sprints, releases, quarters). Scheduling is config, not ledger memory: item lines just carry cycle:<name> and check warns when a name isn’t declared here (P-012). Rollover is manual — nothing auto-advances; declare the next window when you start it. Merged like kinds: repo entries shadow user entries by name.

pub fn kind_table(&self) -> Result<KindTable, String>

The resolved kind table — prelude + this config’s [[kinds]]. Missing kinds = the prelude alone, so zero-config is today’s five kinds.

Source

pub fn validated_cycles(&self) -> Result<Vec<CycleConfig>, String>

The validated [[cycles]] table — unique names, the group-name charset, end > start. Config errors are hard (config is code, not data), unlike the check warnings an undeclared cycle: token earns.

Source

pub fn cycle_on(&self, d: Date) -> Option<&CycleConfig>

The cycle covering d, if any — the window [start, end] inclusive on both ends.
