User keymap — keys.toml overrides for command bindings.

Declarations suggest, users override: action keys[], MenuEntry.keys, and the pavo_core::commands::BUILTINS defaults are suggestions; this file remaps them by command id (the canonical action:<id> | route:<path> | host.<builtin> | driver:<name>:<id> grammar — see pavo_core::commands).

§Location

First readable file wins:

  1. $XDG_CONFIG_HOME/pavo/keys.toml
  2. ~/.config/pavo/keys.toml (when XDG_CONFIG_HOME is unset)

There is deliberately no project-local file — pavo.toml belongs to the config driver’s own layered config; keybindings are a per-user host concern. PAVO_KEYS is not consulted (keep the surface small; add it if a real need shows up).

§Format

TOML. Top-level string/array values are global bindings; tables scope bindings to a driver ([myco]) or a single view (["myco:board"] — quote when the scope contains :). Keys are command ids (quote them — they contain :/.); values are a pavo_core::KeySpec string or an array of spec strings. An entry replaces the declaration’s suggested keys wholesale; command ids absent from the file keep their suggestions.

# ~/.config/pavo/keys.toml
"host.filter" = "ctrl+f"        # global: replace "/" with ctrl+f
"host.palette" = ["ctrl+p", ":"]

[myco]                            # every myco view
"action:todo.done" = "D"

["myco:board"]                    # just the board view
"host.reload" = "R"

Scope precedence per command id: driver:view > driver > global. Specs validate through pavo_core::KeySpec; invalid entries drop out of the effective binding (see pavo_core::commands::effective_bindings).

Structs§

UserKeymap
A parsed keys.toml — bindings partitioned by scope. ""-less design: the global map holds unscoped command ids; scopes maps a scope string ("myco" or "myco:board") to its bindings.

Functions§

binding_value 🔒
A binding value: "spec" or ["spec", …] → comma-joined spec list (the overlay shape effective_bindings consumes). Anything else (42, nested tables, …) is ignored.
keymap_paths
Candidate keys.toml paths in discovery order (first readable wins). See the module docs for the policy.
load
Load the user keymap — first readable candidate wins; missing or unparsable files yield an empty map (bindings fall back to declaration suggestions).
parse
Parse keys.toml source into a UserKeymap. A malformed document yields whatever parsed before the error (toml_edit is all-or-nothing per document — a parse error returns an empty map, matching “invalid file = no overrides”).
