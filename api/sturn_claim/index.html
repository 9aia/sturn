Claims — advisory locks folded out of the WAL. Publish before editing; contenders learn in milliseconds instead of at merge. Pure functions over the event log: same log, same claims, deterministic everywhere it’s computed.

Claim records carry a typed resource URI scheme:path — fs:src/** globs, dev:display0, net:13000, sess:T-012, cap:role. A bare glob with no scheme is fs: — old WALs and scripts keep working unchanged.

Functions§

active
Fold events into live claims at now: Claim upserts on (ws, uri), Release removes, expired TTLs drop. Callers fold all workspaces’ WALs for swarm-wide claims.
conflicts
Live claims that overlap uri — what sturn claim warns about. Overlap is symmetric: an existing src/** claim conflicts with a request for src/foo.rs, and vice versa.
covers
Do two fs paths/patterns overlap? Both may be globs — approximate intersection: match each against the other and against the other’s literal stem. Conservative — it may over-report on exotic globs, and that’s the right failure direction for a lock.
glob_match
Glob match: * = any run within a segment, ** = any run across segments, else literal. Recursive, no deps.
normalize
Canonical URI — bare globs gain fs:, schemes lowercase so fs: and FS: name the same resource.
overlaps
Do two claim URIs overlap? Different schemes never conflict; fs uses glob intersection; net uses port-range intersection when both paths parse, else falls back with every other (opaque) scheme to exact or boundary-prefix match.
split
Split a claim URI into (scheme, path). No valid scheme: prefix → fs (a bare glob is a filesystem claim).
