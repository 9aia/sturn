cuora — the engine as a library. Everything that used to live in the binary lives here: Cli/[Cmd], config load, verb dispatch, audit. run() is the compat CLI’s whole body; drivers (the cuora bin, tamias-driver-cuora’s run/ops surfaces) split it into parse/parse_from + dispatch — argv in, exit code out.

cuora — secrets broker for agents. Sealed, not spilled.

Code and config carry cuora:// references, never values; cuora run materializes declared secrets as env vars in the child only. Every materialization — and every denial/failure — emits an audit event: ndjson on stderr, plus OTLP spans when OTEL_EXPORTER_OTLP_ENDPOINT is set.

Values never enter via CLI args — put/rotate read stdin or a hidden /dev/tty prompt (args land in shell history and /proc). get is the escape hatch that prints a value to stdout; [guardrails] can advisory-deny it for agents.

Functions§

command
The clap verb tree as a [clap::Command] — the ops manifest derives itself from this, so a verb can’t exist on the CLI and be missing from the driver’s wire surface.
dispatch
One parsed command → exit code. The dispatch every driver shares; argv parsing is a caller concern. Audit events stay buffered — callers that own a process exit flush via run/run_from, which also own sigpipe + the flush.
parse
Process argv → a parsed Cli. Split from dispatch so drivers can parse their argv (a run verb, a re-exec) without owning process args. Clap errors/help still exit the process, same as argv parsing.
parse_from
Same, from an argv iterator — parse_from(["cuora", "list"]).
run
The compat CLI body — parse process argv, dispatch, flush audit, hand back the exit code. Owns the process-level concerns the old main did: sigpipe reset before parse and the one audit flush every exit path funnels through.
run_from
Same, from an argv iterator — the run passthrough entry drivers re-exec (tamias-driver-cuora run <cuora argv>).
